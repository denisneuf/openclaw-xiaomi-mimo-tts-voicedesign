⚙️ Cómo funciona

📎 1. El comando

/vd dialogue default-test::Four people. One elevator... || lord-of-the-rings::This is no accident... || ...

🔧 2. Parseo interno

El plugin divide el texto del comando con dos reglas simples:

1. fullText.split("||") → ["default-test:: Four people...", " lord-of-the-rings:: This is no...", ...] 2. Cada parte: indexOf("::") → separa persona del texto

🌐 3. Fetch a MiMo por segmento

Para cada segmento: 1. Busca personas[seg.persona].providers.xiaomi-voicedesign.style en openclaw.json 2. Hace fetch() a api.xiaomimimo.com/v1/chat/completions 3. Payload: { messages: [ { role: "user", content: "<style>" }, { role: "assistant", content: "<texto>" } ], audio: { format: "mp3", optimize_text_preview: <por segmento> } } optimize_text_preview varía según la persona: ├─ 01-narrator: false (default-test sin override) ├─ 02-illuminated: true (lord-of-the-rings, override true) ├─ 03-impatient: false (pirate-captain) ├─ 04-pragmatic: false (russian-heavy) ├─ 05-enjoyer: false (female-soft) ├─ 06-destiny: true (lord-of-the-rings, override true) └─ 07-late: false (pirate-captain) 4. Recibe response.json().choices[0].message.audio.data (base64) 5. Decodifica: Buffer.from(audioData, "base64")

🧩 4. Concatenación de MP3

Cada segmento devuelve un MP3 independiente. Para unirlos sin cortes:

1. El primer buffer se incluye tal cual. 2. Para cada buffer siguiente: - Si empieza con "ID3" (header ID3v2), se salta: const size = (b[6]<<21) | (b[7]<<14) | (b[8]<<7) | b[9]; b = b.subarray(10 + size); 3. Buffer.concat(cleanBuffers) → MP3 sin metadatos duplicados → audio seamless.

3
3. Fetch ×7: cada llamada devuelve un buffer MP3 (base64 → Buffer.from)
4
4. Guardar individuales: writeFileSync(elevator-{id}.mp3, buf) — cada segmento a su archivo

6
6. Crear canvas: HTML con players que apuntan a MiMo-V2.5-TTS-VoiceDesign/elevator-{id}.mp3 (rutas relativas)
