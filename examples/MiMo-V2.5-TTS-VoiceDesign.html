⚡ Referencia rápida

🎮 Comandos runtime
/tts persona <nombre> — Cambia la persona activa al instante. Sin reiniciar.
/tts persona lord-of-the-rings
/tts persona russian-heavy
/tts persona female-soft

/vd optimize <on|off|status> — Controla optimize_text_preview.
/vd optimize on — MiMo puede modificar el texto
/vd optimize off — Texto exacto, sin cambios
/vd optimize status — Ver estado actual
⚠️ El toggle se pierde al reiniciar el gateway
⚙️ Config en openclaw.json
{ "persona": "female-soft", "personas": { "lord-of-the-rings": { "optimizeTextPreview": true }, "russian-heavy": { "style": "Heavy Russian..." }, "female-soft": { "style": "Young female..." } }, "providers": { "xiaomi-voicedesign": { "optimizeTextPreview": false } } }

📊 Precedencia de optimizeTextPreview

  1. providerOverrides — override vía framework
  2. /vd optimize on|off — toggle runtime del plugin
  3. req.personaConfig?.optimizeTextPreview — desde la persona activa en openclaw.json
  4. req.providerConfig?.optimizeTextPreview — desde el provider global en openclaw.json
  5. true — fallback por defecto
Ejemplo: JSON tiene false global + /vd optimize on → gana el toggle → true

🔁 Flujo TTS — de mi mensaje al audio

Cómo OpenClaw procesa una llamada TTS paso a paso

1. 🛠️ tool: tts(text="...") ← yo ejecuto el tool ↓ 2. 🔍 OpenClaw resuelve: · Provider TTS activo: "xiaomi-voicedesign" · Persona activa: "lord-of-the-rings" · De openclaw.json extrae personaConfig: style, optimizeTextPreview ↓ 3. 🧩 Plugin synthesize() · Resuelve style con: providerOverrides → personaConfig → providerConfig → DEFAULT_STYLE · Resuelve optimizeTextPreview con: providerOverrides → /vd optimize → personaConfig → providerConfig → true · Construye payload JSON ↓ 4. 🌐 fetch() → POST api.xiaomimimo.com/v1/chat/completions · Headers: Content-Type: application/json, api-key · Body: { model, messages: [{role:"user",content:style},{role:"assistant",content:texto}], audio: {format:"mp3"} } ↓ 5. 📥 MiMo responde · JSON con choices[0].message.audio.data (base64) · El plugin decodifica: Buffer.from(audioData, "base64") ↓ 6. 📤 Plugin devuelve a OpenClaw · { audioBuffer, outputFormat: "mp3", fileExtension: ".mp3" } ↓ 7. 💾 OpenClaw escribe archivo temporal · Ruta: /private/tmp/openclaw/tts-XXXXXX/voice-<timestamp>.mp3 · /private/tmp es el \$TMPDIR del sistema · openclaw/ es el subdirectorio de OpenClaw · tts-XXXXXX es aleatorio (evita colisiones entre sesiones) · voice-<unix_ms>.mp3 nombre con timestamp ↓ 8. 🔊 OpenClaw entrega al canal · WebChat: stream directo al navegador · iMessage/Telegram: se envía como attachment · El temporal se limpia tras la entrega (excepto si lo copias antes) ↓ 9. ✅ Yo recibo: (spoken) <texto>

📁 ¿Por qué mp3? Porque el plugin usa "format": "mp3" por defecto. MiMo soporta mp3 y wav. El mp3 es más pequeño para transmisión. Si se quisiera wav, habría que cambiar req.providerConfig?.format || "mp3" a "wav".

📁 ¿Por qué /private/tmp/openclaw? macOS enlaza /tmp → /private/tmp. OpenClaw crea /tmp/openclaw/ como su área temporal. Los subdirectorios tts-XXXXXX son generados por fs.mkdtempSync.

💬 Diálogo multi-persona

Comando /vd dialogue persona:: texto || persona:: texto || ...

Formato:
/vd dialogue persona1:: texto || persona2:: texto || persona3:: texto

El comando parsea los segmentos, llama a la API de MiMo para cada uno con el style de la persona correspondiente, y concatena los MP3 en un solo archivo.

Ejemplo probado (2 voces):
/vd dialogue lord-of-the-rings:: You have my sword, old friend. || russian-heavy:: Da. Is good.
2 segmentos, 34 KB → ~/.openclaw/tmp/voicedesign-dialogue-*.mp3

Ejemplo probado (3 voces):
/vd dialogue lord-of-the-rings:: Gandalf speaks first. || russian-heavy:: Viktor answers him. || female-soft:: And the lady whispers softly.
3 segmentos, 65 KB

Flujo interno:
1. fullText.split("||") → partes
2. Cada parte: indexOf("::") → separa persona del texto
3. Busca style de la persona en openclaw.json
4. Llama a MiMo API para cada segmento
5. Concatena buffers MP3 (limpia ID3 del 2+ segmento)
6. Guarda en os.tmpdir() → ~/.openclaw/tmp/
7. Devuelve la ruta del archivo
